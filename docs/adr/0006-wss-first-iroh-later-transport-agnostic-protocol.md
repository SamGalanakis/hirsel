# Transport-agnostic client protocol; WSS first, iroh as milestone two

The client↔host protocol is defined as a transport-agnostic bidirectional message stream (serde types over "a pipe") with no HTTP-isms — no routes, headers, or cookies in the protocol itself. v1 carries it over plain WSS (caddy auto-TLS + bearer token) because the iroh browser leg is the most speculative piece of the stack: no NPM package exists, the wasm wrapper crate would have to be written before the first message renders, and a browser gets a relayed connection anyway — none of iroh's hole-punching benefit, all of its toolchain cost. iroh (node-key auth, no open ports/DNS) stays the target transport and swaps in later as an ALPN carrying the same message stream, touching connection setup only. This deliberately deviates from the original design note that listed iroh as settled for day one.
