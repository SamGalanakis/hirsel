# SHA-256

[API overview](../API.md). [Operations and contracts](../sha256.hirsel).

`std.sha256.hash(bytes)` computes FIPS 180-4 SHA-256 and returns
`Inline[u8, 32]` in network order. `start()` creates a `Sha256` state;
`add(mut state, bytes, lo, hi)` appends the range `[lo, hi)`; `finish(state)`
returns its digest without changing the state. `add_byte(mut state, x)` appends one byte,
so a caller frames its input with tags and lengths without building a buffer. A finished state accepts more
input. Invalid ranges have `list.slice`'s checked semantics. The total length
field is encoded as a big-endian bit count modulo 2^64, as in RustCrypto SHA-2;
FIPS 180-4 defines messages shorter than 2^64 bits.

All five operations allocate nothing and retain no input view. The state has
eight chaining words and a 64-byte pending block. Complete input blocks are read
directly, so streaming separate Key and argument ranges needs no concatenation or
argument copy. `hash` and `add` take O(n) work; `start`, `add_byte` and `finish`
take O(1).

The module extends core's `sha256`, whose `blocks` and `block` compress whole
64-byte blocks ([core library](../../../docs/spec/core.md)). The runtime uses the
CPU's SHA-256 instructions when it has them (the x86-64 SHA extensions or the ARMv8
SHA-2 instructions) and its portable FIPS 180-4 code otherwise; digests, failures,
steps and charges are the same on every CPU. `add` compresses all of its complete
blocks in one core call, and `add`, `add_byte` and `finish` take a fixed number of
steps whatever the input length. RustCrypto `sha2` 0.10.9 with its default
backends, SHA-NI on this host, is the performance reference. The contract laws
cover NIST vectors, a million streamed `a` bytes, and Rust SHA-2 differential
lengths 0 through 200 with every two-chunk split; native engines run each law
with the CPU's instructions and again with `HIRSEL_SHA256=portable`.
