# Verified domain recommendation for #50

**Verdict — recommend optional outcome tracking within the existing Thread identity.** This is a proposed doctrine change, not an adopted design or implementation approval. Conversation/Task modes already mean one Thread model at any depth; optional tracking can encode exactly the same capability. There is no architectural advantage to claim over that proposal. Prefer low-friction creation without a mandatory mode picker, followed by an explicit **Track as task** action (helper copy: “Add the outcome you want”).

An untracked Thread has no completion action. Tracking records the desired outcome using its title/description and starts open; **Mark done** records Owner acceptance, and **Reopen** restores an open commitment. No additional outcome field is justified yet. **Stop tracking** explicitly withdraws an open commitment, never completes it. Removing tracking after completion must preserve the completion record; reopening, withdrawal and later tracking must retain their history rather than erase durable evidence. Keep these actions simple and explicit, with withdrawal explained at the action.

The same conversation, identity and messages remain throughout. Finishability is independent of depth: **Lash** can be an ongoing root or nested conversation; **Fix artifact layout** can be tracked at either level. **Trip planning** can remain exploratory or track an accepted itinerary while containing **Book flights**; Book flights can equally stand alone. No implied child cascade, acceptance dependency, reparenting or worktree change follows.

Preserve Owner acceptance by default. Agents can report finished work or needs input using existing messages/reports and attention. A separate Ready for review enum and delegated permission to mark done are future choices, not prerequisites or shipped rights.

## Accepted, corrected and rejected claims

- **Accepted: current doctrine is universal explicit settlement.** PRODUCT and ADR0016 separate execution, attention, visibility and read state from settlement; the Thread shape has settlement but no tracking eligibility. ADR0016 supersedes the older global-conversation/Task-margin recommendation. Optional eligibility therefore revises current doctrine. State separation itself is already adopted. [H1–H2]
- **Accepted, precisely bounded: persistent terminal-turn presentation.** `status.ts` selects the latest terminal state whenever nothing runs or queues; it does not itself persist data. The row retains that signal, and completed turns display a checkmark labelled “Turn finished.” Every Thread gets Settle/Reopen. This is presentation emphasis, not automatic work completion. [H3]
- **Corrected: generated completion is invocation authority.** A validated displayed instrument action submits a turn, then settles if `settles` is true; it does not await successful work or verify outcome acceptance. Under the recommendation, completion-bearing controls must require tracking and clearly mean Owner acceptance at invocation. [H4]
- **Corrected: plugin scope is not Owner acceptance.** The scoped plugin path can write settlement after caller/subtree authorization, but the installed registry is empty. This matters to a future completion-authority contract only; it is not evidence of shipped agent auto-completion or a new runtime finding/ticket. Ordinary agent update schema exposes attention/instrument, without done/review state. [H5–H6]
- **Accepted with limits: Org supports optional TODO at any heading.** Code permits adding/removing TODO state, configurable descendant blocking and independent manual archive tagging. Automatic parent DONE is documented as an added hook. These establish a coherent comparison, not a requirement to copy dependency rules, state cycling or archival mechanics; they do not establish the proposed durable withdrawal history. [G]
- **Corrected: Plane's separate records are a genuine alternative, not the root's modes proposal.** Written doctrine distinguishes work items/modules/pages; code defines separate Issue, Module and Page models. That alone does not establish conversation continuity or Owner acceptance. Reject introducing separate work records for this scoped need: no demonstrated benefit warrants new ownership/conversion decisions. [P]
- **Rejected: OpenHands proves accepted task completion.** This checkout documents Agent Canvas, a frontend. Code maps execution status into conversation status and separately models automation runs with conversation IDs. Neither establishes human-accepted completion. [O]

## Ranked semantic deltas only

1. **Adjacent to #49:** tracking eligibility determines Track as task / Mark done / Reopen / Stop tracking, explicit outcome copy and outstanding-work filtering. Preserve the existing single hierarchy and contextual parents; do not infer eligibility from roots or children. No responsive-layout or nesting redesign.
2. **Adjacent to #13:** reserve work-completion emphasis for accepted tracked outcomes. Resting ongoing rows should favor conversation recency; retain live execution, attention and explicitly turn-scoped failure/history. This is inventory semantics, not another timeline implementation.

Universal closure with better labels remains the smallest change, but cannot distinguish absent commitment from unfinished commitment. Optional tracking earns its complexity only if that distinction is wanted; binary modes with the same creation/conversion behavior are equivalent.

**Limitations:** bounded static verification only, against the pinned local checkouts below. Both provisional reports were read, followed by peer doctrine and actual code. No builds, tests, product calls, commits or source edits; only this report was written. Peer examples support design reasoning, not empirical UX superiority. All candidates remain unadopted. Issue adjacency uses the supplied exclusion map, not a refreshed tracker audit.
