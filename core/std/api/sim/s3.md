# Simulated S3

[API overview](../../API.md). [Virtual time and plans](world.md). [Simulated DNS and TLS](net.md).

`std.sim.s3.serve(config, plan, clock, take port)` serves a bucket at one
simulated address. Give the client the `Net` from `provide.net` and run
`std.sim.world.run` alongside the server. The returned report describes the
final object map, successful object writes, accepted connections and withdrawn
replies.

Requests use HTTP/1.1 with a fixed content length and one request per
connection. The bucket is selected by the endpoint, so the path is the
object key. Use an S3-canonical URI-encoded path and query. SigV4 uses header
authentication for one access key and credential scope. Seal a prederived
test signing key with the `verify` or `mac` policy. The mock accepts a
signed SHA-256 payload hash or `UNSIGNED-PAYLOAD`. It provides no host network
access.

PUT and multipart completion support `If-None-Match` and `If-Match`. HEAD
returns the object's length, ETag and user metadata. ListObjectsV2 orders keys
lexically and supports prefix, start-after, max-keys and continuation tokens.
ETags are opaque. The mock uses SHA-256 and permits small multipart parts
for bounded tests. The configured body limit also applies to the assembled
object.

A nonempty fault list is indexed by a plan draw at each accepted connection.
Each connection gets a separate fragment stream from the next draw. Use a
scripted plan to prescribe fault choices. A reset before the body leaves the
bucket unchanged. A reset after the body hides the response after dispatch.
Stall delays delivery until an absolute virtual time. The caller's deadline
can withdraw the reply first. An optional second network script takes
effect after the first resolve.
