# Chat output is turn output, not a tool call

The Agent talks to the Owner the way a normal lash chat agent talks to its user: the turn's assistant prose / final value IS the Chat message, delivered by the host when the turn commits (live preview streams via agent_activity while it runs). The earlier `chat.send` tool is removed — routing ordinary replies through a tool call made the default path (just answering) the exception, inverted lash's native model (lash-cli/agent-workbench render turn output directly), and produced silent-swallow bugs when the model answered in prose. `inbox.file` remains a tool because the Inbox is genuinely a side effect with structure (anchor, requires_response, Quick Replies); Chat is not. Consequence: mid-turn permanent chat messages don't exist — live status is the ephemeral activity stream, async output is the Inbox.
