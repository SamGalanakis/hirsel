# Simulated S3

[API overview](../../API.md). [Virtual time and plans](world.md). [Simulated DNS and TLS](net.md).

`std.sim.s3.serve(config, plan, clock, take port)` serves a bucket at one
simulated address. Give the client the `Net` from `provide.net` and run
`std.sim.world.run` alongside the server. The returned report describes the
final object map, successful object writes, accepted connections and withdrawn
replies.

`start_service` creates the provider port, gives it to the simulator task and
returns its typed endpoint and task handle. Pass that endpoint to
`std.object.start_simulated` when a caller needs to know that it is using this
simulator. `endpoint_network` exposes the same Net for wire-level tests.

Requests use HTTP/1.1 with a fixed content length and one request per
connection. The bucket is selected by the endpoint, so the path is the
object key. Use an S3-canonical URI-encoded path and query. SigV4 uses header
authentication for one access key and credential scope. Seal a prederived
test signing key with the `verify` or `mac` policy. The mock accepts a
signed SHA-256 payload hash or `UNSIGNED-PAYLOAD`. It provides no host network
access.

PUT and multipart completion support `If-None-Match` and `If-Match`. GET
supports a single range, optionally pinned with `If-Match`. HEAD
returns the object's length, ETag and user metadata. A matching `If-None-Match` on GET returns 304. The bucket location fixture returns `global`, and its encryption fixture returns `AES256`. ListObjectsV2 orders keys
lexically and supports prefix, start-after, max-keys and continuation tokens.
ETags are opaque. The mock uses the first 128 bits of SHA-256 and permits small multipart parts
for bounded tests. The configured body limit also applies to the assembled
object.

A nonempty fault list is indexed by a plan draw at each accepted connection.
Each connection gets a separate fragment stream from the next draw. Use a
scripted plan to prescribe fault choices. A reset before the body leaves the
bucket unchanged. A reset after the body hides the response after dispatch.
`MalformedComplete` returns a 200 with a code-less error body before publication.
Stall delays delivery until an absolute virtual time. The caller's deadline
can withdraw the reply first. `CutResponse(n)` returns the response head
and at most `n` body bytes before a reset. `RequireResume(n)` checks the
next GET starts at byte `n` and pins the stored ETag. An optional second network script takes
effect after the first resolve.

L1, L2, L3 and L5 run against the standard object client. L4 stops a reference
manifest writer after each wire operation and recovers the highest published
generation. An acknowledged generation is a lower bound. An issued manifest
whose reply was lost can survive if its bytes and packs are complete.

Run the laws and their replay check with the native contract runner:

```sh
python3 core/tools/std_native.py --compiler "$hirsel" --runtime "$runtime" \
  --record-runtime "$record_runtime" --backend cranelift \
  --filter sim_s3:s3_client_laws --replay
```

This runs the contract through `hirsel test --replay` and requires `Sealed`.
