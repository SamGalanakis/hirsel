# SHA-256

[API overview](../API.md). [Operations and contracts](../sha256.hirsel).

`std.sha256.hash(bytes)` computes FIPS 180-4 SHA-256 and returns
`Inline[u8, 32]` in network order. `start()` creates a `Sha256` state;
`add(mut state, bytes, lo, hi)` appends the range `[lo, hi)`; `finish(state)`
returns its digest without changing the state. A finished state accepts more
input. Invalid ranges have `list.slice`'s checked semantics. The total length
field is encoded as a big-endian bit count modulo 2^64, as in RustCrypto SHA-2;
FIPS 180-4 defines messages shorter than 2^64 bits.

All four operations allocate nothing and retain no input view. The state has
eight chaining words and a 64-byte pending block; compression uses a fixed
64-word inline schedule. Complete input blocks are read directly, so streaming
separate Key and argument ranges needs no concatenation or argument copy.
`hash` and `add` take O(n) work; `start` and `finish` take O(1).

The scalar recurrence adapts RustCrypto `sha2` 0.10.9
`src/sha256/soft_compact.rs:14-76` and FIPS 180-4 sections 5 and 6.2.
It uses explicit wrapping u32 addition and no CPU-specific core operation.
RustCrypto's faster portable `force-soft` implementation is the performance
reference. The contract laws cover NIST vectors, a million streamed `a` bytes,
and Rust SHA-2 differential lengths 0 through 200 with every two-chunk split.
