## OpenUI component library

Generated from `app/src/openui/schema.ts` by `node app/scripts/openui-prompt.mjs`.
Do not edit this file by hand.

An `openui` artifact's content is one openui-lang program written against the
component library below. Hirsel draws it natively with its own design tokens, so
it is on-brand without being asked, it renders while it is still being written,
and a line it cannot parse is dropped instead of breaking the page.

Prefer `openui` for anything the Owner reads or operates: dashboards, metric
bands, tables, comparisons, checklists, forms, surveys and suggested replies.
Prefer `solid` only for a custom visualisation or interaction this vocabulary
cannot express, `markdown` for a document, and `html` for a self-contained page
that must stay exactly as authored.

A Button or FollowUp sends an ordinary Owner message back to the artifact's
Thread: the label the person saw, then a fenced JSON block with the artifact id,
the action name, its params and the form state. Read that block to learn what
was chosen, and edit the artifact with `artifacts_edit` — one
`identifier = Component(...)` line at a time — to answer.

The content of an `openui` artifact is one openui-lang program: nothing else, no
markdown fence, no commentary. Everything the Owner should see must be reachable
from `root`.

## Syntax Rules

1. Each statement is on its own line: `identifier = Expression`
2. `root` is the entry point — every program must define `root = Stack(...)`
3. Expressions are: strings ("..."), numbers, booleans (true/false), null, arrays ([...]), objects ({...}), or component calls TypeName(arg1, arg2, ...)
4. Use references for readability: define `name = ...` on one line, then use `name` later
5. EVERY variable (except root) MUST be referenced by at least one other variable. Unreferenced variables are silently dropped and will NOT render. Always include defined variables in their parent's children/items array.
6. Arguments are POSITIONAL (order matters, not names). Write `SomeComp([children], "row", "l")` NOT `SomeComp([children], direction: "row", gap: "l")` — colon syntax is NOT supported and silently breaks
7. Optional arguments can be omitted from the end
- Strings use double quotes with backslash escaping

## Component Signatures

Arguments marked with ? are optional. Sub-components can be inline or referenced; prefer references for better streaming.

### Layout
Stack(children: Component[], direction?: "col" | "row", gap?: "none" | "sm" | "md" | "lg", align?: "start" | "center" | "end" | "stretch", justify?: "start" | "center" | "end" | "between", wrap?: boolean) — Layout container and the root of every program. Stack a column of sections, or a wrapping row of metrics and cards.
Section(title: string, children: Component[], description?: string) — A titled group of related content, with an optional one-line description under the title.
Card(children: Component[], title?: string, description?: string) — A bordered panel grouping components under an optional title.
Separator() — A horizontal rule between groups.
Tabs(items: TabItem[]) — Tabbed panels. Only the selected panel is drawn.
TabItem(value: string, trigger: string, content: Component[]) — One tab: a stable value, the label on its trigger, and the components in its panel.

### Content
Heading(text: string, level?: number) — A standalone heading, level 1 to 3. Prefer Section when the heading introduces a group.
Text(text: string, tone?: "default" | "muted", size?: "sm" | "md") — One paragraph of plain text. Use Markdown when the prose needs lists, emphasis or links.
Markdown(text: string) — CommonMark/GFM prose rendered through the app's own parser. Use for anything longer than a paragraph.
Metric(label: string, value: string, delta?: string, trend?: "up" | "down" | "flat") — One headline number with its label and optional change. Put several in a row Stack to make a metrics band.
Callout(text: string, variant?: "info" | "success" | "warning" | "danger", title?: string) — A short highlighted notice. Use danger only for something that actually went wrong.
Table(columns: string[], rows: string[][], caption?: string) — Row-oriented data table. `rows` holds one array of cell strings per row, in column order.
List(items: ListItem[], ordered?: boolean) — A bulleted or numbered list of ListItem rows.
ListItem(text: string, detail?: string) — One list row. `detail` is right-aligned meta text such as a count or a date.
Image(src: string, alt: string, caption?: string) — An image by URL or data URI. `alt` is required and must describe the picture.
CodeBlock(code: string, language?: string) — Preformatted source or output in the monospace scale.
Chart(variant: "bar" | "line" | "pie", labels: string[], values: number[], title?: string) — A single-series bar, line or pie chart. `labels` and `values` are parallel arrays.

### Interaction
Form(name: string, fields: Component[], buttons: Component[]) — Groups input components under one name and the buttons that submit them. Every field inside is reported under this name.
Input(name: string, label?: string, placeholder?: string, type?: "text" | "email" | "number" | "password" | "tel" | "url", rules?: string[], value?: string, hint?: string) — One-line text field. `rules` are validation strings such as "required", "email", "minLength:3".
Textarea(name: string, label?: string, placeholder?: string, rules?: string[], value?: string, hint?: string, rows?: number) — Multi-line text field for longer answers.
Select(name: string, options: string[], label?: string, placeholder?: string, rules?: string[], value?: string, hint?: string) — Single choice from a list. Use Radio instead when there are three or fewer options worth showing at once.
Checkbox(name: string, label: string, checked?: boolean) — One boolean answer.
Radio(name: string, options: string[], label?: string, rules?: string[], value?: string) — Single choice shown as a group of radio buttons.
Slider(name: string, label?: string, min?: number, max?: number, step?: number, value?: number, hint?: string) — A number chosen from a range.
DatePicker(name: string, label?: string, rules?: string[], value?: string, hint?: string) — A date field. Values are ISO `YYYY-MM-DD` strings.
Button(label: string, action?: string, variant?: "primary" | "secondary" | "outline" | "ghost" | "destructive", params?: Record<string, any>) — Sends one message back to this Thread carrying `action`, `params` and, inside a Form, everything that form holds. A primary button validates its form first.
FollowUp(suggestions: string[]) — Suggested replies. Choosing one sends it to this Thread as an ordinary message.
Every input needs a unique `name`. Put inputs inside a Form so their answers arrive together.

## Hoisting & Streaming (CRITICAL)

openui-lang supports hoisting: a reference can be used BEFORE it is defined. The parser resolves all references after the full input is parsed.

During streaming, the output is re-parsed on every chunk. Undefined references are temporarily unresolved and appear once their definitions stream in. This creates a progressive top-down reveal — structure first, then data fills in.

**Recommended statement order for optimal streaming:**
1. `root = Stack(...)` — UI shell appears immediately
2. Component definitions — fill in as they stream
3. Data values — leaf content last

Always write the root = Stack(...) statement first so the UI shell appears immediately, even before child data has streamed in.

## Examples

root = Stack([band, table, ask])
band = Stack([openRate, replies], "row", "md")
openRate = Metric("Open rate", "38%", "+4pt", "up")
replies = Metric("Replies", "112", "-9", "down")
table = Section("By segment", [segments])
segments = Table(["Segment", "Sent", "Opened"], [["Trial", "820", "310"], ["Paid", "1,240", "470"]])
ask = Form("narrow", [segment], [apply])
segment = Select("segment", ["Trial", "Paid", "Churned"], "Segment", "All segments")
apply = Button("Apply filter", "narrow", "primary")

## Important Rules
- Choose components that best represent the content (tables for comparisons, charts for trends, forms for input, etc.)

## Final Verification
Before finishing, walk your output and verify:
1. root = Stack(...) is the FIRST line (for optimal streaming).
2. Every referenced name is defined. Every defined name (other than root) is reachable from root.

- Keep one statement per line and give each a short, descriptive identifier — an edit replaces exactly one line.
- Use the components below and nothing else. An unknown component name is dropped silently.
- Every input needs a unique `name`, and inputs that are answered together belong in one Form.
- Numbers in a Chart are numbers, not strings; a Table's cells are strings.
