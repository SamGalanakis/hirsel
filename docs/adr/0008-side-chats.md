# Side Chats: seeded forks that produce the Owner's reply

A Ping can be opened into a Side Chat — an ephemeral conversation scoped to that Ping, rendered as a sheet over the main Chat. Three decisions define it. (1) The fork is a *seeded scope*, not a transcript copy: a fresh lash session seeded with the Agent prompt, the Ping + its Anchor exchange, and a bounded window of recent Chat — deterministic and host-built, with no main-Agent turn spent opening one. (2) The Conclusion is the Owner's reply, not the Agent's: the side Agent drafts, the Owner edits/confirms, and the result lands in main Chat as the Owner's Anchor-refed reply. The main Agent reacts like it would to any Quick Reply and never sees the side transcript. (3) Side sessions are ephemeral cattle: concluding auto-resolves the Ping through the shared Owner-reply path and discards the session; topics that outgrow a Side Chat graduate to main Chat. Consequence: protocol frames carry an optional Side Chat scope, and the Tray under Chat is the home for Pings.
