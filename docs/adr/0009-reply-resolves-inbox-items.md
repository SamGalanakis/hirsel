# Replying resolves an Inbox Item; one terminal state, named Done

An Inbox Item has exactly two states: open (needs the Owner's attention) and done (dealt with, kept findable). The Owner replying to an item's Anchor — quick reply, inline reply, or a Side Chat Conclusion — transitions it to done automatically, host-side, the moment the anchor-refed reply lands. This is deliberately mechanical and does not violate ADR-0005's no-policy-code stance: like read-state, it encodes a fact (replied ⇒ handled), not a judgment; judgments — is this item moot, should this resurface — remain Agent cognition via `inbox.resolve` (renamed from `inbox.archive`). Consequences: the Agent must never resolve an item the Owner already replied to (redundant) nor narrate resolutions in Chat; "archived"/"Deleted" vocabulary dies — the UI section is "Done", and there is no separate hard-delete state because for a single-Owner tray one terminal state suffices. The derived replied-state (owner message ref'ing the anchor) remains the display detail on done cards.
